Detail notes

1
Meeting transcripts. Tactiq owned by Victor (works on Teams + Meet); Gemini notes save to the note-taker's personal Drive only. Tactiq is weak on Microsoft Teams; external folks on Teams stay a friction point. Enable Google transcripts for internal meetings.
2
Code repos + Jira / Asana. The index should also surface in-flight Asana tasks, not just code: "not in the codebase yet, Vladimir is on it, talk to him."
3
Knowledge base / RAG. "Once we have the data in one place, anything else can be integrated, even by code." The genuinely new capability is the synthesizer that re-projects all the scattered docs on demand. Maps to the per-engagement context layer (Layer 1) + a knowledge-base synthesizer.
4
Central agent-settings repo. Feedback to the code-review agent edits a knowledge file here (modifying memory, not training the model). Open Q: does the agent update these files itself, or human-reviewed? They shouldn't live on the main branch (don't give the agent write access to main), so stored here or elsewhere.
5
Requirements / alignment agent. Fed: client-call transcripts (the client describing their use case in their own words), business-meeting notes, prior specs.
6
Planner agent. Fed: the spec from step 1, the repo dependency graph + architecture (from the code-intelligence agent), past similar plans. Could also weigh team availability / priorities, a "planner that knows the team."
7
Implementer agent. Fed: plan from step 2, repo conventions / code style / commit format, the relevant client transcripts. Known weak spot: agents don't naturally make code reusable or human-readable, open question what to feed in to fix that.
8
Reviewer agent. Sees the full PR + last ~4 PRs, accumulates repo standards; "some feedback, not human-level, doesn't remove your responsibility to go over almost everything," useful especially on the 2nd pass. Proposal: feed it meeting notes so it knows why conventions exist (today it only sees what's there, and the sensitive review discussion happens outside the PR). Blocker: repos often have no architecture doc (e.g. A6 structural), so you can't tell the agent the intended design. Open Q: can an agent trace logic / run all scenarios in its head, even with full context? Reference: CodeRabbit / Travis-style AI reviewers were partly open-source, check what's in the bucket.
9
Human review. Human-in-the-loop is on the spec and the important calls, not every line. The agent classifies each action auto-run / notify-me / needs my approval, and only the last reaches the phone, never auto-proceeding on a timeout. Reachable from a phone so the laptop isn't the bottleneck.
10
Docs + hooks agent. Pre-/post-commit hooks are deterministic scripts at fixed points in the agent lifecycle (format, lint, tests). They guarantee correctness before a commit lands, since you can't expect a human to read every line in an agent-first workflow.
11
Repo-monitoring auto-fixer. Hooked to monitoring: alert → agent → analyze → maybe fix → PR through review. Also takes the small QA bugs Rossen files (~<1h each); if stuck, brings a human in. Hard prerequisite: strong automated test coverage (unit + integration; design the app to be mockable), or agent fixes introduce regressions. ~90% of these bugs are catchable by tests. Assign it like a teammate (its own account, not just an API key) so its work is trackable; start it on the smallest issues and widen.
12
Code-reuse / dedup agent. Indexes all active repos; the index re-runs on commit. Tackles real cross-team duplication (e.g. SQL agents re-implementing the same code; the weekly "what is each team building" meetings exist partly because of this). Function-level indexing + docstring generation works well today on Python & JavaScript (most training data). Should also surface in-flight Asana tasks, not just code.
13
Personal meeting assistant. Sara already runs one ("removes a stress I didn't understand before"; useful when you've got 7-8 meetings a day and no prep time). Delivery: drops the brief into Google Calendar / pings on Telegram. Plus a "Monday fun-fact" digest from the knowledge base. Runs on a local model (Qwen on the data-center "Impro" box) because it hears personal conversations.
14
Team-orchestration agent. Builds a per-person profile (the "EU AI Act risk-classification" analogy applied to people), then suggests who should do which task, who should talk to whom, and helps phrase the message ("you need to talk to Martin, here's how, given his profile"). The bet: knowledge is globalized, but its interpretation is per-person; agents replace parts of a function, not people, and the weak spot they actually help with is team communication, not writing code.
15
Org-wide PR dashboard. Pipe the code-review agent's output + PR data into a database → a single app showing every PR's status, who's on it, linked to daily-standup notes. Replaces clicking into each repo. Stopgap until built: mark agent-reviewed PRs as draft (or rename them) so they filter cleanly in the existing PR list. (Possible graduation-internship project.)

The takeaways

The bet: the win isn't a smarter coding agent, it's unifying the information internally so every agent (and every human) has the right context. "Knowing what's developed / will be developed" matters; "knowing every step" doesn't, so repetitive meetings get summarized down to a context pack.
Human gate where it counts: on the spec and the important calls, not every line. The agent triages; only high-risk reaches the phone. More agent-first the work gets, the more this matters.
Cost caveat: coding agents are subsidized below true token cost today. IRIS is fine for now (Hero on AWS credits) but the architecture should lean on self-hostable models so a price/policy change isn't fatal.
Known gaps: agents are bad at making code reusable / human-readable ("they don't care"), what do we feed them to fix that? Start the auto-fixer on the smallest issues and widen. Pre-commit hooks guarantee correctness before a commit lands.
