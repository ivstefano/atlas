# Layer 1 — Uniform per-engagement context template

Goal: every `scoping/<client>/` folder carries the same three files, in the same shape, so
any agent (and I) can pick up an engagement cold. These files are **regenerated/updated**,
never hand-maintained from scratch. They are the inputs every Layer 3 loop reads.

Prototype set: **Heineken, Aumovio, SMS** first. Then roll out to all engagement folders.

---

## The three files

### `CONTEXT.md` — the stable picture (changes rarely)

System-prompt-style, factual descriptive voice (matches the style already used in
`scoping/heineken/human-in-the-loop/CONTEXT.md` and the root `CONTEXT.md` work). Sections:

1. **Engagement** — client name, what they do, engagement type (scoping / PoC / PoV / MVP),
   one-paragraph summary of the use case.
2. **The problem** — what the client is actually trying to solve, in their terms.
3. **The Axion/Neuralith angle** — which product, what it does for this use case.
4. **Data** — what data exists, where it lives, format, quality, access status, key
   gotchas (e.g. "tab 'In progress' is source of truth, the rest is derived").
5. **Commercial gate** — what has to happen for this to progress: signed contract? budget?
   a decision from whom? Pricing if known.
6. **Stakeholders** — table: name, org, role (decision maker / SME / engineer / champion),
   availability notes (holidays, OOO).
7. **Current phase** — where in the lifecycle, and what "done" looks like for this phase.
8. **Source pointers** — link to `SOURCES.md`; call out the 2-3 canonical artifacts.

Voice: descriptive, not imperative. No em dashes (commas / colons / parentheses).

### `STATUS.md` — the live log (changes constantly)

Append-only, **newest entry on top**. One entry per meaningful event. Entry shape:

```
## 2026-05-12
- What happened: <one or two lines>
- Blocked on: <thing> — owner: <who> (or "not blocked")
- Next action: <thing> — owner: <me / whom> — by: <date if any>
- Notes: <optional>
```

Meeting notes get **summarized into** `STATUS.md`, not left as raw transcript. The raw
transcript stays in `notes/` (or `tactiq_export/`) and is referenced from `SOURCES.md`.

This file is what the morning brief, the weekly rollup, and the stale-engagement watchdog
read. Keep it honest: blocked means blocked, skipped means skipped.

### `SOURCES.md` — the artifact index ("docs written for the agent")

One line per artifact in the folder, with what it contains and (where relevant) which
sheet/section is the one that matters. This is what lets an agent find the right Excel tab
without me saying "tab 7." Shape:

```
## Canonical
- `Aumovio SOW.md` — active SoW, 10wk / 4 phases / €17.6k. Signature block at end.
- `Template contracted volumes_rev2.xlsx` — target output template.

## Meeting notes / transcripts
- `notes/Aumovio <> Iris 2026-04-29.txt` — week-6 sync, v6 at 71% acc, eval blocker.

## Data samples
- `POC Scoping/Data/1st sample/` — first sample contract set (German/English, F1/F3 types).

## Generated artifacts
- `poc/_extractor/` — 3-step extractor (OCR → LLM extract → Excel fill).

## External
- Drive: <link or path> — proposal GDocs/GSlides.
- Slack: #<channel> — tech-team thread.
```

## Conventions (apply across all engagements)

- **Dates absolute**, never relative ("by next Friday" → "by 2026-05-16").
- **Naming**: meeting notes as `<Client> (<their lead>) <> Iris.ai YYYY-MM-DD.txt` (matches
  the standard already adopted for Agrolimen).
- **No em dashes** in any of these docs.
- **Contract-grade docs** (SoW, NDA): referenced from `SOURCES.md` as canonical, but never
  regenerated by a loop without a human-in-the-loop step (see README §3).
- Auto-memory (`MEMORY.md` + its files) stays as the **cross-engagement** layer; these three
  files are the **per-engagement** layer. A new fact that's specific to one engagement goes in
  that engagement's `CONTEXT.md`/`STATUS.md`; a fact that spans engagements or is about how I
  work goes in auto-memory. Avoid duplicating between the two.

## Migration plan (prototype → rollout)

1. **Heineken**: fold existing `BRIEFING.md`, `TIMELINE.md`, `SCOPING.md`, `SLACK.md`,
   `MEETING_PREP_*` into `CONTEXT.md` + `STATUS.md`; build `SOURCES.md` from the file listing.
   Keep the RAG-grounding `human-in-the-loop/CONTEXT.md` as-is (different purpose).
2. **Aumovio**: `CLAUDE.md` → `CONTEXT.md`; `POC.md` + `notes/` → `STATUS.md`; index `poc/`.
3. **SMS**: `POC_SCOPING_PROPOSAL.md` / `PROPOSAL.md` / `PRE-KICK-OFF.md` / `STORY.md` →
   `CONTEXT.md` + `STATUS.md`; index `poc/`, `table-extractor/`, `__examples/`.
4. Review: does an agent given only these three files draft a usable meeting prep? If yes,
   roll out the template to the remaining `scoping/*` folders.
